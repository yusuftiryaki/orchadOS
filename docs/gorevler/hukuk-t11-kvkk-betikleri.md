## Part 1: T11 scripts
Decision H26: pilot without a deletion feature is acceptable with “yazılı bir başvuru prosedürü, başvuru defteri ..., önceden yazılmış ve gözden geçirilmiş elle silme ve takma ad betikleri (T11)”. T11 (verbatim): “Gözden geçirilmiş elle silme ve takma ad betikleri: owner_profile, parcel_detail iletişim bilgileri, sorular, hissedar daveti; ekleme-yalnız tablolarda takma ada çevirme; çalıştırılınca denetim kaydı.” Decision tree (H26): 1. retention-bound data (fatura, ödeme ve iade, mesafeli sözleşme ve ön bilgilendirme onayları, makbuz) is not deleted; access is limited to proof and tax audit and the request is refused for that part with reasons. 2. Append-only audit and consent records are kept; if needed their identifying fields are pseudonymised “kayda geçirilen kontrollü bir istisnayla”. 3. While the contract runs, data needed for the service cannot be deleted (deletion is possible through termination). 4. Contract ended and no retention basis: delete or anonymise. 5. Another owner or co-owner with a running contract on the parcel: delete only the requester's personal data (“adı, telefonu, hesabı, soruları, kendi siparişlerinin kişisel bağlantıları”); keep the garden data of the other owner's service. 6. A co-owner's request: the account and the invitation link are deleted. 7. Third persons in images: hiding via T20 (not here).
Do:
1. scripts/kvkk/README.md (Turkish): purpose, safety, every command, and a table with one row per covered table/column: rule (erase, pseudonymise, keep), the H26 item it implements, the retention reason for kept data; tables you consciously skip are listed with the reason. Add a short “Yeni tablo eklerken” section for the later streams.
2. scripts/kvkk/run.sh (bash, shellcheck clean): `scripts/kvkk/run.sh <inventory|erase|pseudonymize> (--subject <auth user uuid> | --person-name <text> --parcel <uuid>) --request <başvuru defteri no> [--include-notes] [--apply] [--force-active --reason <text>] [--db-url <url>]`. --person-name serves a person without an account (the boundary pointer, a field contact). Default target: the local stack via docker exec; a hosted database only with --db-url and an interactive confirmation; psql with ON_ERROR_STOP and one transaction; ROLLBACK unless --apply (a dry run prints counts of what would change).
3. inventory.sql: where the subject's personal data is (table, row counts, which rows are retention-bound and why), for the başvuru defteri; it also lists the session_event rows of point 5 whose free-text notes need a manual look.
4. erase.sql: deletes or clears the subject's personal data that has no retention basis: private.owner_profile personal fields, private.parcel_detail contact fields where no other owner's contract continues (only the subject's own entries otherwise), questions and replies authored by the subject (pseudonymise instead if the table is insert-only), viewer invitations by or for the subject, pending sign-ups. 6. Each --apply writes one audit row through private.audit(...) (actions kvkk.erased / kvkk.pseudonymized) with the request number and counts, no personal data.
